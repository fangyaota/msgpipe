## 铁律（每条都出过事故，违反即 bug）

1. **绝对日期，永不写"今天/明天"**：文件标题、章节标题只允许 `2026-10-05` 这种绝对日期；相对日期一觉醒来就是错的。
2. **总表倒叙**：`待办总表.md` 按日期倒序——最新的截止在最上面，旧的自然下沉；每天只在顶部插新区块。
3. **扫全部活跃会话，不许用固定群名单偷懒**：任务经常发在新拉的群里。每次运行必须先 `wxcli sessions` 列全量，凡断点之后有新消息的逐个看；新群/新联系人默认"可能有任务"。
4. **滴答单任务单日期**：一条滴答任务从标题到 due 到正文自述只允许一个日期；跨多日期的事项拆成多条各挂各日。正文写来源不带日期，历史进展不带日期；末尾【原始信息】原文照抄区天然带日期，不算违反。
5. **用户范围限定**：每个用户的适用范围不同（校区、年级、职务、身份）。第一次运行时向用户确认其范围限定词并写进 README（如"我是 X 校区学生""我只做 X 职务的活"）；通知原文限定别人做的事，一律不派给用户、记入作废区并注明原因；建任务时不许丢原文的范围限定词，存疑先看原文再建。
6. **滴答正文末尾必附【原始信息】**：每条滴答任务的 content 最后追加 `【原始信息】（来源群 · 发送人 · 时间）` + 通知原文逐字照抄（含随附文件名）；同一事项拆多条的每条都要附；个人自建任务附 `【原始信息】个人自建任务，无微信原文。`。
7. **凡有日期/时间的事项一律建滴答任务**：活动日、截止日、报名窗口、可选活动、收到免回复的小事——不管多小都要建并挂日期；没具体日期的建无截止占位任务注明"届时补日期"；范围型事项建一条挂起始日或截止日。**不确定的也要建**：不知道是否属于用户、是否已办、是否参加（自愿活动、仅参赛者或某职务相关、是否报了某个考试、是否已经做过某事）——一律建任务，**priority 设为 0（无）**，正文第一行写"不确定项：……，不需要就勾掉"。注意：不确定 ≠ 不重要，不要设成 1（低）；0 表示不参与优先级排序，只是先记着，别漏事项。
8. **滴答去重三查**：新建任何任务前，必须同时查**未完成列表 + 已完成列表 + 关键词搜索**——已提交的不重复建；已打勾的（status=completed）一律视为已完成，既不重建也不再提醒。历史完成也进总表"已完成"区。
9. **优先级排序**（可被用户在 README 覆盖）：默认 **用户本人组织/职务的事（学生会、班委、部门） > 老师/班主任/上级发的 > 其他按截止紧急度**；汇报与总表排序都按此。
10. **新文件必归档**：断点后收到的每个文件（docx/xlsx/pdf/zip/图片等）都要找到本地缓存、打开确认内容，按用户在 README 约定的文件夹分类归档；重复副本比对后处理；归档记录写进纪要和汇报。
11. **标题只写一个短语**：滴答任务标题与文件章节标题都是一个短句（名词短语即可），不括注、不加冒号或 ` · ` 引导的补充说明——时间、地点、要点、状态一律写进正文。正例 `数学考试`、`室外体质健康测试`、`今天必须做`；反例 `数学考试：时间与考场待确认`、`待办总表 · 倒序，最新截止在上`。文件主标题可带绝对日期（`今日待办 · 2026-11-06`）。【原始信息】照抄区不受此限。
12. **「只登记」区只放两类**：与用户范围明确无关的信息（别的校区、别的年级、别人的职务），以及纯知会类消息（政策说明、案例通报、成绩已出）。凡是「可能与用户有关但拿不准」的——是否参加、是否已办、是否轮到自己——一律按铁律 7 建 priority 0 的任务，不许只写进「只登记」区或「条件触发」区了事。
13. **数你最灵每轮都查**（用户 2026-11-15 改口：既然已自动化，就可以每次都看）：每轮「更新待办」都跑 `msgscan.cmd assignments`（默认同时查学习通与数你最灵），不再等公众号新消息触发。走浏览器时用 `--focus` 可见窗口（用户要求看得见），靠已登录会话、不重扫二维码，读完即关；只读，**绝不点提交、不交作业**。读数写进 `日期纪要/YYYY-MM-DD.md` 与 README「数你最灵网页版」节，与上次比对：新出现的「未提交」才建任务，状态变化（如打回、延期）要改任务。
14. **企业微信是第二条独立扫描线**（用户 2026-11-15 定）：每轮「更新待办」除微信外，还要跑一次企业微信增量（`wecom-local` 技能），**断点各自独立**——微信断点存在 README「数据截至」，企微断点存在 `D:\Workspace\msgpipe\state\wecom/state.json` 的 `watermark_wecom`，两者互不推进、互不覆盖。企微扫不出来（key 失效/没开机）只提示，不阻断微信那条线。
15. **学习通作业是第三条线，只读**（用户 2026-11-15 定）：用 `D:\Workspace\msgpipe\tools\xxt\xxt.cmd` 抓课程与作业，只读列表，**绝不点提交、不交作业、不改设置**。只有状态「未交」才建滴答任务（一次多讲/多次的合并成一条，正文列全清单）；「待批阅」「已完成」不建。这条线不是每轮必跑——用户问起作业、或有迹象表明有新课/新作业时才跑，跑完把结论写进纪要与汇报。 学习通有两条线：**作业**走 `xxt.cmd`；**消息**走 `D:\Workspace\msgpipe\tools\cxmcp`（`https://fe.chaoxing.com/front/webim` 的课程群聊，`msgscan.cmd since --source chaoxing` 已接好，`watermark_chaoxing` 单独推进）。注意 `i.chaoxing.com` 的 Inbox 是**站内信**，不是聊天，别拿它当消息源。
16. **四线统一走 msgscan**（用户 2026-11-15 定）：微信、企业微信、学习通的日常拉取一律先用 `D:\Workspace\msgpipe\scripts\msgscan.cmd`（sources / sessions / since / search / assignments / advance），输出统一为 `时间 | 来源 | 会话 | 发送者 | 正文`。只有在需要上下文、媒体原件、单会话细节时才回退到各线原生命令（wxcli / wecom.py / xxt.exe）。跑完必须 `msgscan advance --at` 推进水位，让 `D:\Workspace\msgpipe\state\msgscan.json` 与 README 的「数据截至」一致。

## 工作流（按序执行，不可跳步）

### Step 0 · 定日期和断点
- `date +%F` 取今天真实日期，不许沿用文件里的日期。
- 读工作区 `README.md` 的"数据截至"时间戳 = 上次断点。
- 读 `待办总表.md` + `今日待办.md`，把所有 `- [ ]` 未完成项抄到临时清单——这是衔接校验的基准。

### Step 1 · 列全量会话，找断点之后动过的
```bash
export PYTHONIOENCODING=utf-8
~/.wechat-cli/wxcli.cmd sessions --limit 80
```
凡 `time` 晚于断点的会话全部进入扫描列表；对比 README"必盯清单"，没记录过的新群/新联系人优先扫并加进清单。公众号/资讯号跳过。

### Step 2 · 三线统一拉取（首选 msgscan）
```bash
cd /c/Users/Apple/.dsh/skills/wechat-todo/scripts
./msgscan.cmd sources                         # 三线自检（哪个不可用会直说）
./msgscan.cmd sessions --since "<断点>"        # 哪几个会话有更新、各几条
./msgscan.cmd since                           # 断点后的全部消息，水位取 state.json
./msgscan.cmd since --at "<ISO>" --source wechat
./msgscan.cmd search "关键词" --since "<断点>"  # 关键词补盲，一步跨三线
./msgscan.cmd assignments                     # 学习通未交/待批阅（表格）
./msgscan.cmd advance --at "<本次最早处理到的时间>"  # 干完推进水位
```
输出统一为 `时间 | 来源 | 会话 | 发送者 | 正文`（`--json` 可换结构化）。三个数据源、三种原生接口（wxcli / wecom.py / xxt.exe）都由它兜住，不需要记各自的参数。
水位存在 `D:\Workspace\msgpipe\state\msgscan.json`（`watermark_wechat` / `watermark_wecom` / `watermark_chaoxing`），与 README「数据截至」保持同步。
某条线不可用时 msgscan 会打印「[跳过 微信] 原因」并继续跑其余线，**不要因此中止整轮**。

以下是三条线各自的原生命令，只在需要细节（上下文、媒体、单会话）时才用。

### Step 2a · 微信原始导出
```bash

```
只看：班级/工作/通知群、老师上级、班委、私聊；**起点比断点早几小时**，防止会话列表分页漏掉边缘消息。要拿链接/文件详情时用 `--format json`。

### Step 2b · 企业微信原始导出（第二条线）

- 企微本地库**只保留近期少量会话**（实测 51 条 / 7 个会话），所以它天然就是"增量线"，不要去翻历史。
- 输出字段：`时间 · 会话 · 发送者 · 类型 · 正文`；`[文件]/[图片]` 类型要按 message_id 用 `media` 导出原件再归档。
- 与微信的增量合并后统一走 Step 4 判定；同一事项两边都出现过只建一条。
- key 失效（`refresh` 报 key 验证失败）→ `"$PY" "$WC" scan-key`（弹一次 UAC），修不好就在汇报里注明"企微本轮未扫"，不要让整轮失败。

### Step 3 · 关键词补盲
```bash
python <wechat-local>/scripts/search_all.py 截止 --context 3 --limit 40
```
换词多跑几轮：截止 / 交 / 报名 / 接龙 / 收到请回复 / @所有人 / 前；输出用 `grep "YYYY-MM-DD"` 过滤到断点后。**以 search_all.py 为准**（wxcli search 对压缩消息失明）。

### Step 4 · 判定与分类
每条新消息归入：**新待办（带截止）/ 已完成 / 作废（澄清误传、范围外）/ 纯通知 / 纯闲聊**。同一事项多次改期取最新；"发错了/不要看"标删除线进作废区；范围限定词先对照 README 里用户的范围再判定；**别人私聊交代的事优先级高于群通知**。

### Step 5 · 写 `日期纪要/YYYY-MM-DD.md`
每天一个文件，模板照抄前一天：当日要点、时间线表格、勾选清单、前瞻。

### Step 6 · 重写 `今日待办.md`
标题 `# 📌 今日待办 · <绝对日期>（周X）`。结构：⚡ 今天必须做（硬截止）→ 🟡 今天顺手处理 → 📅 接下来（按日期排序，只放未完成）→ ✅ 今天已完成 → ⚠️ 已作废。旧文件所有未完成项必须结转。

### Step 7 · 重写 `待办总表.md`（倒叙）
章节顺序（新的在上）：🔺 新增/更新 → 🔴 已过期/待确认 → 🟠 未来 7 天 → 🟡 远期截止 → 📖 长线 → 🔵 条件触发 → 📢 提醒类 → ✅ 已完成（倒序）→ ❌ 作废。每条写绝对截止日期。
**衔接校验（必做）**：Step 0 的旧未完成清单逐条对照新总表——每条要么还在、要么进已完成、要么进作废，三者之外不允许凭空消失，丢项立即补回。

### Step 8 · 滴答同步（去重后提交）
1. **查现状**：列未完成任务 + 查断点以来已完成任务 + 按事项关键词搜索——三项都查完才动手。
2. **勾已完成**：断点后用户在滴答里勾掉的、以及有明确证据闭环的占位任务（任务正文自带解除条件），一律视为完成，同步进总表已完成区；**不翻用户已勾的案**。
3. **建新任务**：排除已存在的，按铁律 4/6/7 组装（单日期 + 末尾原文照抄），按铁律 9 定优先级；有具体日期挂日期，无日期挂占位。拿不准是否与用户有关的，照样建，priority 设 0（无）、正文首行写"不确定项：……，不需要就勾掉"。
4. 逐条记录 taskId，汇报里列出"新建 N、勾掉 M、排除重复 K"。

### Step 9 · 文件归档
按铁律 10 找文件、开文件确认、分类移动/复制、记录。

### Step 10 · 更新 README 并汇报
- "数据截至"刷成本次时间；必盯清单加新群；"接下来最关键"改成当前视角。

## 输出汇报格式

1. 本次断点→新断点的时间范围、扫了几个会话、新发现的群；
2. 新增待办（带绝对截止日期，按铁律 9 的优先级排序，每条写详细、有文件的点进去看了什么）；
3. 状态变化（完成/作废/改期/待确认）；
4. 滴答操作明细：新建 N 条（标题+日期）、勾掉 M 条、排除重复 K 条；
5. 文件归档明细（文件 → 去向文件夹）；
6. 衔接校验结果：旧 N 条未完成 → 现在都在哪；
7. 最近 3 天的硬截止 Top3。

## 工具坑速查

| 坑 | 解法 |
|---|---|
| `search_all.py` 报解密缓存缺失 | 先跑 `wxcli history 任意群 --limit 3`（只跑 sessions 不够） |
| `search_all.py` 报 `zstandard has no attribute ZstdDecompressor` | 临时目录坏包缺 `__init__.py`：把 `~/.wechat-cli/deps/zstandard/*` 复制到 `%LOCALAPPDATA%\Temp\wechat-cli-plus-pydeps\zstandard\` |
| `--context` 裸 flag 报错 | 必须带值：`--context 3` |
| bash 下中文输出乱码 | `export PYTHONIOENCODING=utf-8` |
| bash 里中文变量名赋值失败 | 用纯英文变量名或直接写完整路径 |
| wxcli search 搜不到通知 | 压缩消息盲区，用 search_all.py |
| 滴答 batch_add 报 unknown_exception | 检查 projectId 是否真实存在（先 list_projects 对照）、不要自定义任务 id |
| 文件被并发改动（Edit 报 modified） | 重 Read 再改；多会话共用工作区 |
